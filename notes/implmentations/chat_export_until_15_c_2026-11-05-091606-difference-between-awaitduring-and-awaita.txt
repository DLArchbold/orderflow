> Difference between await().during() and await().atMost()

● Both are Awaitility settings, but they answer opposite questions.

  await().atMost(d) is a timeout. It polls until the condition becomes true,
  then returns immediately. It fails only if the condition never becomes true
  within d.
  - Use it for "this should eventually happen". Example: the consumer receives
    the event within 10s.

  await().during(d) is a hold. The condition must stay true for the whole
  duration d. It fails as soon as the condition turns false at any poll. If the
  condition is false at the start, it also fails, because there is no grace
  period.
  - Use it for "this must not change". Example: no duplicate arrives for 3s
    after the first event.

  Using both

  You can chain them. await().during(2s).atMost(10s) means the condition must
  become true and then stay true for 2s, all within 10s.

  In your test

  Your test is "the event arrives once", so the two fit different steps:
  - atMost waits for the first event to show up.
  - during afterward checks that the count stays at 1, which catches duplicate
    publishes.

  await().atMost(Duration.ofSeconds(10))
         .untilAsserted(() -> assertThat(received).hasSize(1));

  await().during(Duration.ofSeconds(3))
         .atMost(Duration.ofSeconds(5))
         .untilAsserted(() -> assertThat(received).hasSize(1));

  Without the during check, an atMost check passes the moment the count reaches
  1. It would miss a duplicate that arrives 500ms later.
