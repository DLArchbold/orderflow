## Before you start (24a)
1. Turn on billing alerts in your AWS account. Create an IAM Identity Center user, or an IAM user with MFA. Don't use root keys.
2. Run `aws configure sso`, then `aws sts get-caller-identity` to confirm you're on the right account.
3. Pick one region and use it for everything, so the cleanup check covers a single region.

## Apply in stages (refer to notes\implmentations\aws_manually for detailed steps)
Run each command from `phase2/infra/terraform`. Run `terraform plan` before each apply and read it.

1. **Budget first.** Run `terraform init`, then `terraform apply -var budget_email=you@example.com -target=aws_budgets_budget.monthly`.
2. **Foundations.** Apply the network, ECR and RDS. RDS takes about 10 minutes.
3. **Push images.** Run `terraform output push_images_commands`. The images must be `linux/amd64`, which a Windows build produces.
4. **Create the databases.** Run `terraform output -raw db_init_command | sh`, then check the `/orderflow/db-init` log group. This also proves RDS is reachable from inside the VPC.
5. **Everything else.** Run `terraform apply -var image_tag=<sha>` to bring up Kafka, Keycloak, the services and the ALB.
6. **Smoke test.** Open `terraform output app_url`, log in as `alice`, and create an order. It should reach CONFIRMED.
7. **## Deploy under load (24c) (see below)**

Expect failures on the first real `plan` or `apply`. The README says `validate` doesn't prove the resources will create. Likely trouble spots are Keycloak's issuer and `KC_HOSTNAME` (the plan allows `jwk-set-uri` as a fallback), the health-check paths, and IAM permissions. Record each fix in [ADR 0006](phase2/docs/adr/0006-aws-choices.md), because your notes track errors for interviews.

## Deploy under load (24c)
Status 2026-11-13: preparation done (baseline restored, second image `dc1acc0` pushed); the k6 run, deploy and destroy are not done yet. Details in [step_7_1_deploy_under_load_prep.md](step_7_1_deploy_under_load_prep.md).
1. Build and push a second image with a new SHA tag. Have the `terraform apply -var image_tag=<new sha>` command ready in a second terminal.
2. Start k6 against the ALB URL at a steady arrival rate for about 5 minutes. Use the k6 script from your load-test step. Write its output to a file, for example `--out json=` plus the console summary.
3. At about the 2-minute mark, run the apply with the new tag.
4. Record the arrival rate, duration, image sizes and the `http_req_failed` count. Only claim "0 failed requests" if the output shows it. Don't call it zero-downtime unless the evidence supports that.

## Destroy and verify
1. Run `terraform destroy`.
2. In the console, in your one region, check for leftovers: load balancers, RDS instances and snapshots, ECR images, CloudWatch log groups, Elastic IPs, and NAT gateways (there should be none).
3. Check Cost Explorer the next day.
