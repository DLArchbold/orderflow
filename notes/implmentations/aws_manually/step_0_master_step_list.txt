## Detailed steps for - Deploy under load (24c)
Secrets injection (the first part of 24c) is already in the Terraform: the DB and Keycloak secrets use `valueFrom`, and the execution role has `GetSecretValue`. Here are the extra substeps, in order.

## A. Prerequisites (do before anything else)

1. **Tools.** k6, aws, terraform and docker are all installed on this machine.
2. **AWS login.** Run `aws sts get-caller-identity`. If it fails, run `aws sso login`.
3. **Clean git tree.** Run `git status`. The image tag is a commit SHA, so a dirty tree gives an image that doesn't match its tag.
4. **Note the baseline tag.** Look at `terraform.tfvars` and the live task definitions to find the tag that is currently deployed. Your notes say `9ff11d1`. `terraform.tfvars` is git-ignored, so the `-var` flag is the only record of the tag.
5. **Verify the secrets injection.** It is already coded. Confirm it works live:
   - In the console, open an order-service task definition and check that the `secrets` entries point at Secrets Manager.
   - Run `aws secretsmanager list-secrets --region us-east-1` and check that the db and keycloak secrets exist.
   - Check that no plaintext password appears in the task definition's environment.
   - A running task that connects to RDS proves the injection works.

## B. Restore the baseline

6. Run `terraform plan -var "image_tag=<baseline>"` and read it. Then apply it.
7. Wait for all services to reach 1/1. Check the target groups for healthy targets: `aws elbv2 describe-target-health --target-group-arn <arn>`.
8. Kafka restarted with no volume, so check that order-service reconnects. If Kafka came up after order-service, look at the order-service logs for Kafka connection warnings. If it stays unhealthy, force a new deployment of order-service.

10. **Check the databases exist.** The one-off `db_init` task only needs to run again if RDS was recreated. If it was, run the `db_init_command` output.

## C. Prepare the second image

11. Make a small real change, for example a log line, and commit it.
12. `$tag = git rev-parse --short HEAD`.
13. Log in to ECR using the throwaway `DOCKER_CONFIG` approach from your redeploy notes.

## D. Prepare the load test

18. **Get the ALB URL.** `$url = terraform "-chdir=$tf" output -raw app_url`.
19. **Smoke-test k6.** Run it for 30 s at 10/s. The ALB routes `/realms/*` to Keycloak, so `KEYCLOAK_URL=$url` works. The token issuer must match `KC_HOSTNAME`, which is the ALB URL.
20. **Find a clean rate.**
    - Run 1 minute at 25/s.
    - Require 0 failed requests, 0 dropped iterations and a p95 under 500 ms.
    - If it fails, lower the rate.
    - Stop and look at why before testing the deploy, because a failing baseline makes the deploy result meaningless.
21. **Check the k6 token lifetime.** The tokens last 30 minutes. Keep smoke tests and the real run within one `setup()` each, since `setup()` fetches fresh tokens every run.
22. **Create the output folder.** `phase2/docs/k6-runs/aws-deploy`. Choose a duration of 8 minutes if the rollout needs it (see section F).

## E. Watch tools for the run

23. **Open the ECS console** on the order-service Deployments tab.
24. **Open CloudWatch Logs** for order-service, to see the new task start up.
25. **Check ALB metrics.** The CloudWatch ALB metrics `HTTPCode_Target_5XX_Count`, `HTTPCode_ELB_5XX_Count` and `TargetResponseTime` give a second source of evidence besides k6. Note the time window.
26. **Prepare a status loop** in a third window, so you have timestamps of when each service finished rolling out:

```powershell
while ($true) { Get-Date -Format T; aws ecs describe-services --cluster orderflow --services order-service inventory-service frontend --region us-east-1 --query "services[].[serviceName,deployments[].[status,rolloutState,runningCount]]" --output text; Start-Sleep 15 }
```
