> Can you explain further? What's an ALB? What is a Dockerfile and why would
  frontend/Dockerfile need additional build arguments to point at the ALB?

● ALB (Application Load Balancer)

  An ALB is an AWS service that gives your app one public address and forwards
  incoming web requests to the right container behind it. In your setup it's the
  single front door.

  - A request to /api/... goes to order-service.
  - A request to the Keycloak login path goes to Keycloak.
  - Everything else goes to the frontend.

  Terraform creates it as aws_lb.main. Its address looks like
  http://orderflow-123456.us-east-1.elb.amazonaws.com, and terraform output
  app_url prints it. That address doesn't exist until AWS creates the load
  balancer, which is why I said you won't know it until later.

  Dockerfile

  A Dockerfile is a recipe for building a container image, which is a packaged
  copy of your app plus everything it needs to run.

  Yours has two stages:

  1. Build stage: it installs the Node packages and runs npm run build. That
     compiles your React or Vite code into plain static files.
  2. Final stage: it copies those files into an nginx web server image. That
     image is what you push to ECR and what ECS runs.

  Why I raised build arguments

  A build argument (ARG in a Dockerfile, --build-arg on the command line) feeds
  a value into the image while it is being built. That matters for frontend apps
  because tools like Vite often paste settings such as an API URL or login URL
  into the JavaScript at build time.

  If your frontend did that, it would hit a problem:

  - The ALB URL isn't known until after Terraform has created the load balancer.
  - The image has to be built before that, because ECS needs it.
  - So the image would have a wrong URL baked in, and you'd have to rebuild and
    re-push after learning the real one.

  I raised it as a risk to rule out, since I hadn't looked at your Dockerfile
  yet. When I checked, your project avoids the problem.

  How yours avoids it

  Your image has no URL baked in. When the container starts, nginx writes a
  small file, /config.js, containing the login URL. That value comes from an
  environment variable that ECS gives the container. The page loads /config.js
  and reads the URL from it. Changing the URL means changing the ECS setting and
  restarting the container, not rebuilding the image.

  That's why the plain docker build command is enough, and you can push the
  frontend image before the ALB exists.
