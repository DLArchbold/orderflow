> Throughout this entire step 4, what were the causes of the issues that we
  encountered along the way?

● The four problems all had one of two causes. Three came from the half-built
  Terraform state, and one from using bash habits in PowerShell.

  Root cause: targeted applies left the state half-built

  Earlier steps used -target (for example -target=aws_ecr_repository.app) and a
  destroy script. That left some resources in state and others missing.
  Terraform only creates what a target pulls in as a dependency, so anything
  nothing depends on gets skipped.

  1. db_init_command was null. The output needs the ECS cluster and the db-init
     task definition, and neither existed after the teardown. Terraform returns
     null for an output it can't build. After I told you to create them with a
     targeted apply, it was still null. A targeted apply doesn't recompute
     outputs when some of their dependencies (the subnet and security group)
     weren't targeted. terraform apply -refresh-only, or a full apply,
     recomputes it.
  2. The task failed with AccessDeniedException on Secrets Manager. The
     execution role existed, but aws_iam_role_policy.execution_secrets didn't.
     That policy is what lets it read the DB secret. Nothing references that
     policy, so the targeted apply that created the task definition and role
     never created it. The Terraform code was correct, and the resource was
     simply never applied. Applying it and re-running the task fixed this. The
     task that failed stayed in its failed state, so you had to launch a new
     one.

  Separate cause: PowerShell is not bash

  3. sh not recognised. ... | sh is bash syntax, and Windows PowerShell has no
     sh. Invoke-Expression (or Git Bash) replaced it.
  4. taskId length should be one of [32,36]. I wrote the describe-tasks command
     with a bash \ line continuation, which PowerShell doesn't use. aws received
     the backslash as part of the task ID. That one was my mistake in the
     command I gave you. Putting the command on one line fixed it.

  One that wasn't a real problem

  5. aws logs tail --follow seemed to hang. It never exits by design. It waits
     for new log lines until you press Ctrl+C.

  What to do to avoid this

  Run a plain terraform apply when you can. It keeps the state, the outputs and
  the IAM policies in sync, and you only need -target for something deliberate.
  You still have a few skipped resources (the Keycloak secret policy, the
  services and the ALB), and a full apply will create those too.
