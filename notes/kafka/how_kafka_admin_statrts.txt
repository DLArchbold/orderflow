    How `KafkaAdmin` starts: you do not start it yourself. With `spring-kafka` on the classpath, Spring Boot's `KafkaAutoConfiguration` registers a `KafkaAdmin` bean built from `spring.kafka.*` (mainly `bootstrap-servers`). It implements `SmartInitializingSingleton`, so Spring calls it once all singleton beans exist, during application startup. It then collects every `NewTopic` bean (your `orders.events`), opens an `AdminClient` connection, checks which topics exist and creates the missing ones. If a topic exists with fewer partitions than the bean asks for it adds partitions, but it never deletes topics or reduces partitions. If Kafka is down, `fatalIfBrokerNotAvailable` is false by default, so it waits up to its operation timeout (about 30 s), logs a warning and lets the app finish starting. This happens only once, at startup: if Kafka comes up later nothing retries it, and the publisher would fail to send to a missing topic (unless the broker has `auto.create.topics.enable` on) until you restart the app.
