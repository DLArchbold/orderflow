## Infrastructure and docs

- [docker-compose.full.yml](phase2/infra/docker-compose.full.yml) runs a single-node Kafka (`apache/kafka:3.8.0`, KRaft mode, so no ZooKeeper). `KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092` is what lets apps on your host connect. Containerized apps would need a second listener, which matters in steps 22–24.
- **Not running:** [infra/docker-compose.yml](infra/docker-compose.yml) (the Phase 1 one) mentions Kafka only in a comment. Kafka comes only from the `full` file, which explains your warnings.
- [phase2/docs/adr/0001-transactional-outbox.md](phase2/docs/adr/0001-transactional-outbox.md) and [architecture.md](phase2/docs/architecture.md) explain why the outbox pattern is used.
- The k8s manifests and `main.tf` have Kafka settings for steps 23 and 24.

## How the pieces fit together

```
order-service                         Kafka                 inventory-service
create order + outbox row  ->  OutboxPublisher  ->  orders.events  ->  OrderEventsListener
   (one DB transaction)         (poll, send, ack)                      (reserve stock,
                                                                        write result event)
```

The outbox exists so you never save an order without sending its event, or send an event for an order that rolled back. The database and Kafka can't share a transaction, so the order and the outbox row are saved together. A separate publisher then forwards the row to Kafka.

## Gaps you'll hit

- **Only one topic is referenced:** `orders.events`. The result topic that step 15 needs (inventory to order-service) doesn't exist yet. Neither does a dead-letter topic for step 16.
- **No producer in inventory-service:** `application.yml` has only consumer settings. It will need producer settings, or an outbox of its own, to publish the result event.
- **No order-service Kafka config:** there is nothing yet in `services/order-service`, as expected before step 12.
- **Topic creation:** I found nothing that creates `orders.events`. With a default broker, auto-creation may do it on first send. For a real setup, declare a `NewTopic` bean or create the topic in compose.
